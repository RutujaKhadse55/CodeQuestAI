# 1. LeetCode Data Acquisition Design

**Principle:** we only use what the learner is looking at, on their own machine, when they ask for help. We do not crawl, bulk-download, or touch editorials, discussions, other users' submissions, contests, or hidden tests.

## 1.1 Three Sources (all read in the browser by the extension's content script)

| Source | What we read | How | Reliability |
|---|---|---|---|
| **A. Page DOM** | Title, difficulty, statement text, examples, constraints, selected language, the learner's **selected code** | Content script reads visible elements using selectors from a single config file (`selectors.config.ts`, 2 fallbacks each); selection API for code | Medium — LeetCode changes its DOM; fallback = user selects the statement manually |
| **B. LeetCode page API (public problem metadata)** | `titleSlug`, statement HTML, `exampleTestcases`, `codeSnippets` (Python 3 starter), `topicTags`, difficulty | `fetch('/graphql')` from the content script (same-origin, uses the page's own session), query on `question(titleSlug: …)` — an **unofficial** interface `[VERIFY field names]` | Medium — can change without notice; use only as an upgrade over DOM |
| **C. Run/Submit result panel** | After the learner clicks **Run**: verdict (Wrong Answer, Runtime Error, Time Limit Exceeded), failing **input**, **output**, **expected**, stdout, error text | `MutationObserver` on the result panel, user-triggered only | Medium — this is LeetCode's own judge output, a valuable ground truth for the failing visible case |

**Priority:** B for structured metadata, A as fallback and for code selection, C whenever the learner runs code. Everything is optional; any single source is enough for explanation mode.

## 1.2 What We Never Fetch

Editorial/solutions tabs, discussion posts, other users' code, submission history of others, contest problems, hidden test cases, anything while the learner is on a contest URL. The extension shows **"Disabled here"** on `/contest/`, `/solutions/` and editorial pages. (Hint integrity: a Hint Guard is pointless if the extension runs beside the editorial.)

## 1.3 Captured Data Contract (`LCProblem`)

| Field | Source | Notes |
|---|---|---|
| `slug` | URL / API | Primary key with `source="leetcode"` |
| `title`, `difficulty`, `tags[]` | A/B | |
| `statement_text` | A/B | HTML stripped to text; ≤ 8,000 chars |
| `examples[]` | A/B | `{input_text, output_text}` as shown on the page |
| `constraints_text` | A/B | Used by the AI to build input generators |
| `starter_python` | B/A | Class `Solution` with the method signature |
| `lang_selected` | A | Only `python3` is executed; other languages = explanation-only |
| `captured_at`, `content_hash` | extension | Hash of statement text for caching |
| `run_capture?` | C | `{verdict, input, output, expected, stdout, error}` |

## 1.4 From Page Text to Runnable Tests (the hard part — owned jointly, see §6)

1. **Example parsing (Backend):** LeetCode formats examples as `nums = [2,7,11,15], target = 9` and output `[0,1]`. Parse each `name = value` pair with a safe tokenizer + `ast.literal_eval`; map to parameter order from the starter signature.
2. **Signature handling (Backend):** LeetCode code is `class Solution: def twoSum(self, nums: List[int], target: int) -> List[int]`. The harness instantiates `Solution()` and calls the method; plain functions are also supported.
3. **Reference bundle (AI):** from statement + constraints + signature, produce and validate:
   - `oracle_bruteforce` — slow, obviously correct, used for correctness checks.
   - `reference_solution` — clean, loop-structured solution that **uses the same parameter names as the starter signature**, used for the tracer and for mutants. Must agree with the oracle on the fuzz set; otherwise discarded and the tracer falls back to final-output comparison.
   - `gen_inputs(rng)` — a per-problem input generator honouring constraints (sorted, unique, "exactly one solution", ranges). Validated: 50 generated inputs run through the oracle without error and satisfy the examples' shape. Fallback: type-driven generator.
   - `comparator` — `exact`, `unordered` (e.g. Two Sum "any order"), or `float_tol`, inferred from the statement.
   - `verified` — true only if the oracle reproduces **all** visible examples (and the run-capture expected output when present).
4. **Verdict labelling:** every result shows **oracle-verified** or **unverified**. If unverified: explanation-only mode (no fuzz verdicts).
5. **Cache:** bundle stored per `content_hash` so each problem is generated once.

## 1.5 Replay Mode (demo safety, still LeetCode-only)

Because LeetCode's DOM or network can change on demo day, the extension can load a **snapshot** of a problem the team captured earlier from LeetCode (`fixtures/lc/<slug>.json`, produced by the capture feature itself). The UI shows "Snapshot captured from LeetCode on <date>". Live capture stays the default; replay is the fallback and also lets AI/Agents/Backend develop before the Frontend capture exists.

## 1.6 Compliance Notes (act on these in the first 30 minutes)

- The booklet's data rule (earlier discussion) says to use fictional or self-built data and avoid live third-party systems. **Ask the organisers whether reading the learner's own LeetCode page is acceptable**; if not, the snapshot/replay mode is the position to argue (the data is user-selected and stored locally).
- LeetCode's terms and its unofficial API can change `[VERIFY]`. Keep requests single-problem, user-triggered, rate-limited (≥ 1 s between calls), and never store problem text in the public repo beyond the small fixtures needed for tests (keep fixtures private or in a gitignored folder if the repo is public).
- Never run on live contests; never claim affiliation with LeetCode.

# 3. Conflict-Avoidance System (the heart of parallel work)

Merge conflicts in hackathons come from five things: two people editing the same file, shared config files, shared JSON/locale files, dependency lists, and unstable interfaces. Each is eliminated below by design, not by discipline.

## 3.1 The Ten Rules

| # | Rule | How it prevents conflicts |
|---|---|---|
| 1 | **Path ownership.** Every directory/file has exactly one owner (see §4). `CODEOWNERS` enforces it. Nobody edits a path they do not own | Two people never touch the same file |
| 2 | **Contracts first.** At T+0:45 `backend/app/contracts/` (pydantic models + Python `Protocol`s) and `openapi.yaml` are frozen. After that: **additive changes only** (new optional fields), each acked by producer and consumer | Interfaces are stable before implementation starts |
| 3 | **Fakes for everything.** Each owner ships a `fakes.py` implementing their Protocol with canned data in Phase 0–1 | Consumers never wait for producers |
| 4 | **Auto-registered routers.** `main.py` discovers `routers/*.py` automatically; each router file is owned by one role | No one edits `main.py` to add an endpoint |
| 5 | **Per-owner DB model files.** `db/models_core.py` (Backend), `models_ai.py` (AI), `models_agents.py` (Agents); `db/__init__.py` imports all; `create_all()` at start (no migrations) | No shared `models.py` |
| 6 | **Namespaced locale and prompt files.** `locales/<lang>/ui.json` (Frontend), `mentor.json` (AI), `chat.json` (Agents); prompts in `ai/prompts/*.txt`, `agents/prompts/*.txt` | No shared JSON files, which merge badly |
| 7 | **Split dependency files.** `requirements/base.txt` (Backend), `ai.txt`, `agents.txt`; `package.json` only Frontend. Root `requirements.txt` just `-r` includes them | No single list everyone edits |
| 8 | **Split env examples.** `env/backend.env.part`, `ai.env.part`, `agents.env.part`; `make env` concatenates into `.env.example` | No shared `.env.example` conflicts |
| 9 | **Feature flags** in `config.py` read from env (`FEATURE_CHAT`, `FEATURE_MEMORY`, `FEATURE_VOICE_AGENT`, …). Unfinished work merges behind a flag that defaults to **off** | `main` is always shippable |
| 10 | **Merge windows, not merge chaos.** Small PRs merge any time **only if** they touch the author's own paths and `make smoke` passes; integration happens in fixed windows (§8) in a fixed order (Backend → AI → Agents → Frontend) | Predictable integration, producers before consumers |

## 3.2 Change-Request Protocol (when you need something in someone else's area)

1. Post in chat: `[REQ Frontend→Backend] need field verified_at in /analyze response — by T+3:30`.
2. Owner replies within 10 minutes with ✅ ETA, or ❌ + alternative.
3. If the owner is busy, the requester may open a PR **touching only the named file**, tag the owner, and wait for a 👍. Contract changes always need the producer + consumer ack.
4. Never "just fix it" in another person's directory.

## 3.3 Branches

- One long-lived branch: `main`. Always runnable: `make run` and `make smoke` pass.
- Short branches: `feat/<role>/<topic>` (e.g. `feat/ai/reference-synth`), ≤ 90 minutes of life.
- Commit format: `type(scope): message` (`feat(sandbox): class Solution harness`).
- Before any merge: `git fetch && git rebase origin/main && make test && make smoke`.
- **Integration owner** (rotates per phase, see §8) holds the merge window and runs the full smoke test.

## 3.4 Definition of Done (applies to every task)

1. Merged to `main` behind a flag if incomplete.
2. A test or scripted `curl` proves it (path in PR).
3. Conforms to the frozen contract; errors use the common error body.
4. Has a **fallback** when the LLM or ElevenLabs is down.
5. Does not weaken a guard (hidden-test secrecy, Hint Guard, sandbox).
6. Owner ran it once from a clean terminal.

| 1 | T−10 min | Everyone pushes their branch, rebases on `main`, runs own tests. Announce "ready" in chat |
| 2 | T−5 | **Integration owner** (below) merges in order: **Backend → AI → Agents → Frontend** (producers before consumers; contracts always first) |
| 3 | T | After each merge run `make test` (module tests) |
| 4 | T+2 | Run `make smoke` (Appendix B). Flip `USE_REAL_*` flags that now have real implementations |
| 5 | T+5 | If smoke fails: owner of the failing step fixes within 10 minutes; if not fixed, **revert that merge commit** (`git revert -m 1 <sha>`) and keep the flag off |
| 6 | T+10 | Announce "main green" with commit SHA; everyone `git pull --rebase` and continue |

**Integration owner by window:** MW0 Backend · MW1 Frontend · MW2 Agents · MW3 AI · MW4 Backend · MW5 Frontend. Rotating spreads understanding of the whole system and avoids a single bottleneck.

## 8.2 Between Windows (continuous integration without conflicts)

- Small PRs that touch **only your own paths** may merge at any time if `make test` and `make smoke` pass.
- Anything crossing a boundary (new field, new function a teammate needs) goes through the change-request protocol (§3.2).
- Use flags for unfinished code: `FEATURE_CHAT`, `FEATURE_MEMORY`, `FEATURE_PROFILE`, `FEATURE_VOICE_AGENT`, `FEATURE_ORACLE_FOREIGN`, `USE_REAL_AI`, `USE_REAL_VOICE`, `USE_REAL_ENGINE`.
- `main` must always run `make run` — never merge a failing import.

## 8.3 Why This Order

| Order | Reason |
|---|---|
| Backend first | Owns contracts, DB core and the engine everyone calls |
| AI second | Depends only on Backend's `Engine`; Guard and reference builder are consumed by Agents |
| Agents third | Consumes Engine, Hint/Guard, Translator, Learner model |
| Frontend last | Consumes every API; its merge reveals integration mismatches immediately |

## 8.4 Handling Conflicts Anyway

| Situation | Resolution |
|---|---|
| Same-file conflict (should be rare) | The file's **owner** resolves; requester reviews the result |
| Contract mismatch found at integration | Producer adds an additive field or adapter; consumer adjusts; both ack. No renames after freeze |
| Dependency clash (two versions) | Backend decides the pin in `requirements/base.txt`; others adapt |
| A merge breaks smoke | Revert, fix on branch, re-merge in the next small window |
| Late feature | Merge behind a flag set to off; enable only if smoke is green |

## 8.5 Freeze Rules

- **8:30 feature freeze:** no new features; bug fixes only.
- **9:30 release freeze:** only manager-approved hotfixes; every hotfix re-runs smoke and rebuilds the zip.

## 11.1 Risk Register

# Appendix A — Contracts (frozen at T+0:45)

```python
# backend/app/contracts/models.py  (pydantic)
class Example(BaseModel): input_text: str; output_text: str
class RunCapture(BaseModel): verdict: str; input: str|None; output: str|None; expected: str|None; stdout: str|None; error: str|None
class LCProblem(BaseModel):
    slug: str; title: str; difficulty: str; tags: list[str]
    statement_text: str; examples: list[Example]; constraints_text: str
    starter_python: str|None; lang_selected: str; content_hash: str
    run_capture: RunCapture|None = None
class ReferenceBundle(BaseModel):
    oracle_code: str; reference_code: str; gen_inputs_code: str
    comparator: Literal["exact","unordered","float_tol"]; constraints: dict
    verified: bool; notes: str|None = None
class TestResult(BaseModel):
    kind: Literal["example","run_capture","fuzz"]; outcome: Literal["passed","wrong_output","runtime_error","timeout"]
    input: str|None; expected: str|None; actual: str|None   # fuzz => None (never shown)
    failure_class: str|None
class Divergence(BaseModel): iteration: int|None; variable: str|None; expected: Any; actual: Any; line: int|None
class Diagnosis(BaseModel):
    mistake_class: str|None; confidence: float; failure_class: str|None; divergence: Divergence|None
class NeutralMessage(BaseModel):
    kind: Literal["diagnosis","hint","concept"]; mistake_class: str|None; failure_class: str|None
    divergence: Divergence|None; tier: int|None; concept: str|None
class GuardResult(BaseModel): passed: bool; retries: int; source: Literal["llm","template"]
```

```python
# backend/app/contracts/protocols.py
class Engine(Protocol):                                   # Backend
    def sandbox_run(self, code: str, signature: str, tests: list[dict], timeout_s: float = 2.0) -> list[TestResult]: ...
    def fuzz(self, learner_code: str, bundle: ReferenceBundle, seed: int, n: int = 200) -> "FuzzResult": ...
    def trace(self, reference_code: str, learner_code: str, args: Any) -> Divergence | None: ...
class HintState(Protocol):                                # Backend
    def allowed_level(self, user_id: str, problem_key: str) -> int: ...
    def record_hint(self, user_id: str, problem_key: str, level: int) -> None: ...
class Mastery(Protocol):                                  # Backend
    def release_pending(self, user_id: str, attempt_id: int) -> None: ...
class ReferenceBuilder(Protocol):                         # AI
    def build(self, problem: LCProblem) -> ReferenceBundle: ...
class Diagnoser(Protocol):                                # AI
    def diagnose(self, fuzz_vector: str, problem_slug: str, divergence: Divergence|None) -> Diagnosis: ...
class Explainer(Protocol):                                # AI
    def render(self, msg: NeutralMessage, lang: str, profile: dict|None) -> str: ...
class Guard(Protocol):                                    # AI
    def check(self, text: str, ctx: "GuardContext") -> GuardResult: ...
class Translator(Protocol):                               # AI
    def translate(self, text: str, lang: str) -> str: ...
class LearnerModel(Protocol):                             # AI
    def summary(self, user_id: str) -> dict: ...
    def style(self, user_id: str) -> dict: ...
class RubricScorer(Protocol):                             # AI
    def score(self, transcript: str, rubric: dict, lang: str) -> tuple[float, str]: ...
class Memory(Protocol):                                   # Agents
    def remember(self, user_id: str, d: Diagnosis, problem_title: str) -> str: ...
    def recall(self, user_id: str, d: Diagnosis, k: int = 3) -> list[dict]: ...
    def delete_user(self, user_id: str) -> None: ...
class VoiceService(Protocol):                             # Agents
    def tts(self, text: str, lang: str) -> "TTSResult": ...
    def stt(self, audio: bytes, lang: str|None) -> "SttResult": ...
```

**Frozen enums:** `Outcome`, `Lang (en, hi, mr)`, `HintLevel 1–4`, `Verified (oracle-verified, unverified)`, `MistakeClass`, `FailureClass`, common error codes (`UNAUTHORIZED`, `FORBIDDEN`, `VALIDATION_ERROR`, `RATE_LIMITED`, `CODE_REJECTED`, `HINT_LOCKED`, `UNSUPPORTED_PROBLEM`, `UNSUPPORTED_LANGUAGE`, `CREDIT_CAP_REACHED`, `UPSTREAM_FAILED`).
